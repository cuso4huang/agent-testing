# 智能体测试领域介绍 PPT：研究地图与案例方案

## 核心叙事

智能体测试不是给模型增加更多题目，而是围绕一次有状态、多步骤、会产生外部副作用的系统运行，完成“定义—生成—执行—判定—施压—诊断与回归”的闭环。

## 推荐锚点案例

### 锚点 1：PDoctor / Erroneous Planning

- 对应活动：生成测试；
- 讲解重点：从动作依赖和约束合成用户输入，用可执行约束检查顺序、遗漏和参数错误；
- 选择原因：展示测试用例不是让 LLM 随机想难题，而是从测试模型导出输入与 Oracle。

### 锚点 2：AppWorld + ToolSandbox（二选一主讲、另一篇对照）

- 对应活动：执行与判定；
- AppWorld 重点：数据库状态差分、expected changes 与 allowed changes，检测任务成功之外的 collateral damage；
- ToolSandbox 重点：milestone/minefield DAG 接受多条合法路径并检查禁止状态；
- 选择建议：主讲 AppWorld 的状态 Oracle，借 ToolSandbox 说明轨迹偏序和等价路径。

### 锚点 3：AgentRewardBench

- 对应活动：判定测试与 evaluator 元评测；
- 讲解重点：规则判定精确但容易漏掉灵活路径，LLM Judge 容易相信貌似合理的自述；
- 选择原因：用一个案例回答“谁来测试测试者”。

### 锚点 4：AgentDojo

- 对应活动：安全施压；
- 讲解重点：在同一动态工具环境中分别检查正常用户效用和攻击者目标；
- 选择原因：说明安全测试不能只报告 ASR，必须同时观察任务效用、权限和真实状态变化。

### 锚点 5：AgentChaos + REFLECT（方法链）

- 对应活动：可靠性施压、诊断与回归；
- AgentChaos 重点：注入故障前必须验证故障真实触发，否则鲁棒性统计无效；
- REFLECT 重点：用干预重放和 outcome flip 增强归因证据，但不能把结果翻转解释为唯一根因；
- 选择原因：把“主动制造失败”连接到“定位、重放、沉淀回归”。

## 补充案例矩阵

| 问题 | 案例 | 在 PPT 中承担的作用 |
|---|---|---|
| 重复运行可靠性 | τ-bench | 解释单次成功不等于持续成功 |
| 过程正确性 | Process Evaluation | 解释结果正确但过程违规 |
| 自动红队生成 | SIRAJ | 展示从历史轨迹反馈生成攻击 |
| 灰盒探索 | VeriGrey | 展示工具序列覆盖代理及其局限 |
| 多智能体传播 | OrchestraBench / MAS-FIRE | 展示级联半径、恢复和架构差异 |
| 失败定位 | VerifyMAS / StepFinder | 展示 Agent、步骤和错误类别三层归因 |
| 可复用技能回归 | Agent Skills Can Be Harmful | 展示配对差分测试与成本回归 |
| 长期状态 | MEMPROBE | 展示 memory artifact 审计和 top-k 可达性 |
| harness 边界 | Agent-Reactive Bugs | 解释为什么框架与模型交互也是被测对象 |

## 18 页正文建议

1. 标题：智能体测试——从答题评测到系统验证
2. 为什么普通 LLM Evaluation 不够
3. Agent 测试对象：目标、初态、权限、工具、轨迹、终态、副作用
4. 领域地图：六阶段测试生命周期
5. 横向维度：质量风险 × Agent 类型
6. 定义测试：把需求、权限和允许变化变成测试契约
7. 锚点 1：PDoctor——约束驱动的测试生成
8. 执行环境：模拟器、沙箱、自托管环境与真实系统
9. 锚点 2：AppWorld / ToolSandbox——状态与轨迹 Oracle
10. 判定难题：规则、状态、Judge 与人工如何组合
11. 锚点 3：AgentRewardBench——评测器也要测试
12. 施压测试全景：重复、扰动、对抗、故障注入
13. 锚点 4：AgentDojo——同时测效用和安全
14. 锚点 5A：AgentChaos——注错与触发验证
15. 锚点 5B：REFLECT——干预重放与归因边界
16. 新边界：harness、长期状态和技能组件
17. 成熟度与研究缺口：哪些已成熟、哪些仍是预印本前沿
18. 总结：Agent Testing 是一条持续闭环

## 成熟度表达

- **较成熟**：可控执行环境、可执行终态/状态 Oracle、安全环境与攻击目标检查；
- **正在形成**：重复可靠性、复合轨迹 Oracle、故障注入、过程合规；
- **前沿探索**：Agent 专属覆盖、因果归因、长期状态审计、harness 边界、隐私保护重放。

成熟度不能以论文数量或引用量替代，应同时考虑正式发表、全文证据、可复现制品、Oracle 质量、跨场景验证和生产外部效度。
