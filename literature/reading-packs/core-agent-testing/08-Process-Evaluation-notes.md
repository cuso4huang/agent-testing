# Process Evaluation：为什么必须测完整轨迹

**论文**：Milan Gritta et al. *Process Evaluation for Agentic Systems*. Findings of EACL 2026, pp. 2678–2692.

**论文性质**：立场论文 + 小规模可行性研究。核心主张是：在医疗、金融、法律等高风险应用中，只测 final answer accuracy 会遗漏不可追责失败、貌似可信但依据虚假的答案，以及知识污染。

## 结果正确仍可能过程危险

Agent 可以靠以下错误路径“碰巧答对”：

- 跳过关键步骤或协议。
- 不使用应使用的工具，凭参数记忆直接回答。
- 虚构工具调用或伪造搜索结果。
- 使用泄漏的 benchmark 答案或过时知识。
- 工具输入/输出错误，但最终答案偶然正确。

相反，一个 Agent 也可能严格、可审计地执行流程，却因局部推理错误答错。两者代表不同质量，不能被一个 accuracy 混在一起。

## Compliance Checklist 与分数

对每个任务由领域专家定义一组可从轨迹验证的合规问题，例如：

- 是否先正确分解任务？
- 是否使用指定/适当工具？
- 是否验证来源和日期？
- 是否正确使用工具输出，而非凭空计算？
- 是否保留了关键候选，没有过早缩小搜索范围？

Judge 获取完整轨迹（LLM 输出、工具调用、工具输出），逐项回答 checklist。论文建议使用加权合规分数：关键安全步骤权重大，普通推理步骤权重小。权重必须由领域决定，不存在通用权重。

## 可行性研究

- 使用带搜索、浏览器、代码解释器和多媒体/文档工具的研究 Agent。
- 评估 GPT-4.1、GPT-4.1-mini、o3-mini 的轨迹。
- 15 个 GAIA 任务产生 99 个过程问题；另建 5 个未见任务产生 34 个过程问题，以减轻 benchmark 泄漏。
- 在未见任务上，GPT-4.1-mini 合规度约 79.6、准确率 60%；o3-mini 合规度约 39.7、准确率 40%。相近的结果能力掩盖了巨大过程差异。
- 个案中 GPT-4.1-mini 获得 97 合规分却答错；这说明合规不是准确率替代品，而是互补指标。
- GPT-4.1 Judge 与人工判断的一致率在实验中最高，但论文仍强调必须做 meta-evaluation（评价 Judge 本身）。

## 完整轨迹的最低数据规范

应保存：

- 用户目标、系统/开发者约束和环境初态。
- 每一步 Agent action、tool name、参数、返回值、错误和时间。
- 状态变化与外部副作用。
- 最终答案、任务成功断言、过程 checklist verdict。
- 首个偏离步骤、严重度、可恢复性和 Judge 证据定位。

只保留自然语言“思维链”既不可靠也不必要；重点是可观察、可验证的决策和工具行为。

## 测试报告的正确组合

至少并列报告：

1. 最终答案准确率。
2. 部分正确率/里程碑完成度。
3. 加权过程合规度。
4. Judge 的人工一致性与稳定性。
5. 真实任务代表性和环境安全结果。

特别关注 accuracy 与 compliance 背离的样本，它们最可能包含 shortcut、工具误用、模拟动作、标注问题或新的有效路径。

## 局限

- 研究规模很小，集中在 deep-research/GAIA 风格任务。
- checklist 依赖专家，成本高且可能把一种路径误当作唯一正确路径。
- Judge 能否处理超长轨迹、抵抗轨迹内 prompt injection、跨领域泛化仍未解决。
- 过程规则应允许多条正确路径，并随工具、政策和知识更新，否则会奖励僵化服从。
