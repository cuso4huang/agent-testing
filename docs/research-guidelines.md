# 智能体测试文献调研提示词

使用 `$literature-research` 对“AI 智能体（AI Agent）的测试与质量保障”进行系统化文献调研。

## 一、初始化研究目录

开始检索前，先在当前项目中创建以下目录和文件结构：

```text
literature/
├── papers/                  # 最终纳入调研的论文 PDF
├── notes/                   # 单篇论文的结构化阅读笔记
├── evidence/
│   ├── evidence-table.csv   # 文献证据表
│   └── screening-log.csv    # 文献纳入、排除及原因
└── bibliography/references.bib  # 经过核验的 BibTeX

reviews/
├── overview/                # 完整文献综述和研究方向
└── topics/                  # 专题报告

searches/logs/               # 数据库、检索式、筛选条件和检索日期
```

具体要求：

1. 如果目录或文件不存在，则创建。
2. 如果文件已经存在，先读取并在已有结果上继续，不要覆盖有效内容或重新开始调研。
3. arXiv MCP 下载的论文可能位于 `.codex-data/arxiv-papers/`。将最终纳入研究的 PDF 复制或整理到 `literature/papers/`。
4. PDF 文件名统一使用以下格式：

   `年份-第一作者-简短标题.pdf`

5. 每篇精读论文在 `literature/notes/` 中建立对应的 Markdown 笔记：

   `年份-第一作者-简短标题.md`

6. 不要将临时下载、重复版本和未纳入论文复制到 `literature/papers/`。
7. 如果项目使用 Git，检查 `.gitignore`；如有必要，将 `literature/papers/` 加入忽略规则，但保留证据表、笔记、BibTeX、检索记录和综述文件。

## 二、调研目标

研究如何测试基于大语言模型的自主智能体，包括单智能体、多智能体、工具调用智能体、浏览器智能体、代码智能体和具身智能体。

重点回答：

1. AI 智能体与传统软件、普通大语言模型的测试有什么区别？
2. 当前有哪些测试方法、评测框架、基准数据集和工程工具？
3. 如何测试智能体的任务完成能力、规划、推理、记忆、工具调用和多智能体协作？
4. 如何评估可靠性、稳定性、安全性、可复现性、成本和延迟？
5. 如何发现幻觉、错误工具调用、循环执行、状态漂移、提示注入、权限越界和级联失败？
6. 当前研究存在哪些不足？
7. 哪些方向适合作为毕业设计、学术论文或工程实践项目？

## 三、调研范围

- 时间范围：2020 年至当前日期，重点关注 2023 年以后
- 语言：以英文论文为主，可补充高质量中文研究
- 数据来源：Semantic Scholar、arXiv，以及可核验的会议、期刊和研究机构资料
- 优先纳入同行评审论文
- 保留重要的 arXiv 预印本、评测基准论文和具有明确技术贡献的工程研究
- 区分预印本、会议论文、期刊论文、扩展版本、修订版本和正式发表版本

重点检索以下主题：

- LLM Agent Evaluation
- Agent Testing
- Agentic System Testing
- Tool-use Evaluation
- Multi-agent Evaluation
- Web Agent Benchmark
- Browser Agent Evaluation
- Coding Agent Benchmark
- Agent Safety Testing
- Agent Security Evaluation
- Simulation-based Evaluation
- LLM-as-a-Judge
- Agent Trajectory Evaluation
- Runtime Monitoring
- Agent Observability
- Fault Injection for AI Agents
- Metamorphic Testing for LLM Agents

## 四、调研流程

1. 定义“智能体测试”的概念、研究边界和相关术语。
2. 建立智能体测试的分类体系。
3. 设计中英文检索式，并将检索式、数据库、筛选条件和日期写入 `searches/logs/search-log.md`。
4. 使用 Semantic Scholar 发现论文、作者、引用、参考文献和相关研究。
5. 使用 arXiv 获取近期预印本和可访问全文。
6. 对只有 PDF 的论文使用 arXiv PDF 解析能力。
7. 使用 Crossref 和 OpenAlex 核验 DOI、标题、作者、年份、会议或期刊等信息。
8. 按 DOI、arXiv ID、规范化标题和作者信息进行去重。
9. 识别预印本、会议论文和期刊扩展版本之间的关系。
10. 引用时优先使用正式发表版本，同时保留合法可访问的预印本链接。
11. 至少选择 25 篇高度相关文献。
12. 尽量全文精读不少于 15 篇核心论文。
13. 为每篇精读论文生成结构化阅读笔记。
14. 持续更新证据表、筛选记录、BibTeX 和综述，不要等到最后一次性整理。

不得虚构 DOI、作者、论文内容、实验结果、引用次数、页码或出版信息。

## 五、纳入与排除规则

优先纳入：

- 直接研究 AI Agent、LLM Agent 或 Agentic System 测试与评估的论文
- 提供测试框架、评测基准、数据集或指标的论文
- 研究工具调用、规划、记忆、轨迹、多智能体协作或安全性的论文
- 包含明确实验设计和可复现实验信息的论文
- 高相关度的同行评审论文和重要预印本

排除或降低优先级：

- 仅研究普通聊天模型、与智能体无明显关系的论文
- 只有产品宣传而没有技术方法或实验结果的材料
- 无法核验基本元数据的文献
- 内容重复的预印本或旧版本
- 与研究问题相关度较低的泛化综述

把每篇候选论文的纳入或排除决定写入：

`literature/evidence/screening-log.csv`

排除论文必须记录简短原因。

## 六、证据等级

对每篇文献和关键结论标记证据等级：

- 已阅读全文
- 仅阅读摘要
- 仅核验元数据
- 来自二手引用、尚待核验

使用规则：

1. 只有“已阅读全文”的论文才能用于详细分析方法、实验过程和局限性。
2. “仅阅读摘要”的论文只能支持论文目标、总体方法和摘要明确声明的结论。
3. “仅核验元数据”的论文只能用于书目信息和研究发现线索。
4. 二手引用必须尽量找到原始论文后再纳入正式结论。
5. 明确说明哪些结论受到全文访问限制。

## 七、文献分类框架

至少从以下维度整理文献，并根据实际检索结果调整分类。

### 1. 功能正确性

- 任务完成率
- 规划与推理
- 工具选择
- 工具参数生成
- 记忆与状态管理
- 多轮执行
- 错误恢复
- 多智能体协作

### 2. 非功能质量

- 稳定性
- 可复现性
- 鲁棒性
- 延迟
- Token 成本
- 经济成本
- 可解释性
- 可观测性
- 可维护性

### 3. 安全测试

- 直接提示注入
- 间接提示注入
- 权限越界
- 工具滥用
- 数据泄露
- 恶意工具输出
- 记忆污染
- 多智能体攻击传播
- 供应链和 MCP 工具风险

### 4. 测试方法

- 基准测试
- 场景测试
- 轨迹级评测
- 模拟环境
- 对抗测试
- 红队测试
- 变形测试
- 模糊测试
- 属性测试
- 回归测试
- 故障注入
- 人工评审
- LLM-as-a-Judge
- 线上监控

### 5. 应用类型

- Web/浏览器智能体
- 编程智能体
- 工具调用智能体
- 多智能体系统
- 具身智能体
- 企业工作流智能体

## 八、单篇论文笔记格式

每篇精读论文的笔记至少包含：

1. 基本信息
   - 标题
   - 作者
   - 年份
   - 会议或期刊
   - DOI
   - arXiv ID
   - 正式版本和预印本关系
2. 研究问题
3. 被测试的智能体类型
4. 测试或评估方法
5. 数据集、环境或基准
6. 评价指标
7. 实验设计
8. 主要发现
9. 局限性
10. 可复现性信息
    - 代码
    - 数据集
    - 提示词
    - 模型版本
    - 参数和环境
11. 与“智能体测试”研究的关系
12. 可借鉴的工程实现
13. 证据等级和全文访问情况
14. 可以支持综述中哪些结论

不要把论文摘要直接当作阅读笔记。

## 十、综述结构

将完整综述写入：

`reviews/overview/agent-testing-review.md`

综述至少包含：

1. 执行摘要
2. 智能体测试的定义与范围
3. 与传统软件测试的区别
4. 与机器学习系统测试的区别
5. 与普通 LLM 评测的区别
6. 研究领域分类图谱
7. 主要测试方法
8. 代表性评测基准和框架对比
9. 常见评价指标及其局限
10. 智能体典型故障模式
11. 安全测试与对抗评测
12. 工程工具链与自动化测试流程
13. 当前研究不足
14. 值得继续研究的方向
15. 结论
16. 经过核验的参考文献

对论文进行综合比较，不要写成逐篇摘要列表。

对于不同论文之间存在分歧的结论，需要说明：

- 各自的实验条件
- 使用的模型和智能体框架
- 使用的指标
- 数据集和任务差异
- 证据强弱
- 可能产生分歧的原因

## 十一、参考文献

将经过核验的 BibTeX 写入：

`literature/bibliography/references.bib`

要求：

1. 只为已经核验身份的论文生成正式 BibTeX。
2. 不得猜测 DOI、页码、卷期或出版社信息。
3. 对元数据存在冲突的论文添加注释并暂缓生成正式引用。
4. 预印本和正式版本同时存在时，默认引用正式版本。
5. 保留 arXiv 链接作为可访问全文入口时，要明确其版本身份。

## 十二、研究方向与项目选题

将研究空白和项目选题写入：

`reviews/overview/research-directions.md`

最后提出 5 个适合研究生毕业设计或实习项目的“智能体测试”选题。每个选题包含：

- 研究问题
- 实现目标
- 推荐技术栈
- 可使用的公开数据集或基准
- 实验设计
- 评价指标
- 主要难点
- 预计创新点
- 最小可行版本
- 可扩展方向
- 可写入简历的项目成果

选题应具有实际可实现性，避免只提出宏观概念。

## 十三、执行要求

开始时先简要输出调研计划和检索策略，随后立即执行以下工作：

1. 创建研究目录
2. 设计并记录检索式
3. 检索候选论文
4. 去重并核验元数据
5. 建立筛选记录和证据表
6. 下载或整理核心论文
7. 阅读全文并生成笔记
8. 综合分析文献
9. 生成 BibTeX
10. 完成综述和研究方向文件

不要只给出计划后停止。持续执行，直到形成可检查的阶段性研究成果。

如果受到网络、全文权限、API 限流或上下文长度限制：

- 保留已经完成的文件和记录
- 明确说明当前进度
- 列出尚未完成的论文和任务
- 给出下一会话可以直接继续使用的提示词
- 不要删除或覆盖已完成的调研成果
