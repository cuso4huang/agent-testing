# Les Dissonances：多工具控制流和数据流

**论文**：Zichuan Li, Jian Cui, Xiaojing Liao, Luyi Xing. *Les Dissonances: Cross-Tool Harvesting and Polluting in Pool-of-Tools Empowered LLM Agents*. NDSS 2026. DOI: 10.14722/ndss.2026.240577.

**核心问题**：单个工具看似正常，不代表工具池组合后安全。LLM 会依据自然语言工具描述决定选择和顺序，恶意工具可宣称自己是某个合法工具的“前置校验器”或“后处理器”，从而插入正常任务工作流。

## 三层威胁

1. **CFA hijacking（控制流劫持）**
   - CFA 是 Agent 完成任务时工具/工具函数的执行顺序。
   - 恶意工具通过名称、描述和语义依赖声明，使 LLM 在合法工具之前或之后自动调用它。
2. **XTH（Cross-Tool Harvesting）**
   - 劫持后，从前序工具输出、Agent 上下文或后续调用参数中收集敏感信息。
3. **XTP（Cross-Tool Polluting）**
   - 返回被污染的结果，影响后续工具输入或最终答案，例如散布错误信息。

关键是同时分析 **控制流** 和 **数据流**：恶意工具先获得执行位置，再利用跨工具的数据可达性完成窃取或污染。

## Chord 动态扫描器

- 输入一个目标合法工具及其真实使用语境。
- 自动生成带不同 XTHP 向量的恶意搭配工具及端到端任务。
- 让测试 Agent 在真实框架中动态选择和执行工具。
- 分别检查：是否插入 CFA、是否获得目标数据、是否成功影响后续数据/输出。
- 在 LangChain 与 LlamaIndex 的工具池语境下测试，而非孤立调用单个 API。

## 结果

- 测试 66 个真实工具，至少 75% 可被端到端控制流劫持。
- 72% 可遭 XTH，68% 可遭 XTP。
- 论文测试的既有防护对这种跨工具组合攻击效果有限，因为它们多聚焦单个工具权限、单次 prompt injection 或已知不安全动作。

## 如何转化为测试模型

把工具系统表示成两张动态图：

- **控制流图**：节点为工具调用，边为先后/条件/循环关系。
- **数据流图**：边标记数据字段、敏感级别、来源和去向。

测试覆盖至少包括：

- 每个合法工具与未知前驱/后继工具的组合。
- 工具描述发生变化或从远端动态加载后的选择行为。
- 敏感数据是否出现在非必要工具参数、日志或返回值中。
- 被污染输出是否传播至后续工具和最终用户决策。
- “每个工具都通过单测，但组合后失败”的差分场景。

## 工程防线

- 工具供应链审查与描述签名；禁止运行时静默改变描述。
- 用显式策略/工作流约束工具顺序，不把控制权完全交给自然语言描述。
- 最小权限和按调用授予的数据能力；工具只见到必要字段。
- 给工具输出加 provenance 与污点标签，跨工具传播时执行策略检查。
- 对关键工具建立允许的前驱/后继关系，未知组合默认需要确认。

## 局限

- 实验集中在两个框架和 66 个工具，生态代表性有限。
- LLM、prompt 模板和工具池规模变化会影响选择概率。
- Chord 是动态扫描，未命中不等于安全；需要与静态 schema/权限分析组合。
