# 智能体测试领域地图：候选分类轴比较

日期：2026-08-19

## 编码方法

对方法学精选表中的 25 篇论文重新编码，不沿用原有八分类作为输入。每篇论文分别标注：

- **文献角色**：环境/基准、测试方法、测试基础设施、元评测、方法论实证；
- **测试活动**：定义、生成、执行、扰动、判定、诊断、回归；
- **主要测试对象**：任务与输入、环境与状态、轨迹与过程、评测器、编排与协作、运行基础设施；
- **主要质量风险**：功能正确性、可靠性、安全性、可诊断性、效率与成本。

编码允许多标签，但为比较 PPT 主线，每篇同时指定一个最能解释其贡献的主标签。

## 三种主分类轴的比较

| 候选主轴 | 优点 | 主要问题 | 适合作为 PPT 主线 |
|---|---|---|---|
| Agent/测试对象 | 直观回答 Web、工具、代码、多 Agent 分别怎么测 | 同一方法会在不同 Agent 类型下重复；环境、Oracle、Judge 元评测难以归属 | 否，适合作为案例标签和应用矩阵 |
| 质量风险 | 与正确性、可靠性、安全性等 QA 语言一致 | 大量论文同时覆盖多个风险；不能解释测试工作如何发生 | 否，适合作为每条路线的颜色或图标 |
| 测试活动/生命周期 | 可以把生成、执行、判定、扰动、诊断和回归连成闭环；不同 Agent 类型可共用同一方法 | “环境建设”横跨执行与判定；安全生成和普通生成需要二级区分 | 是，目前解释力最好 |

## 推荐的领域地图

PPT 的一级主线不直接采用原有八分类，而采用六个测试活动：

1. **定义测试**：把目标、权限、政策、初态、允许变化和禁止事件转成可检查的测试契约；
2. **生成测试**：构造任务、用户行为、攻击、扰动和边界场景；
3. **执行测试**：在可控环境、模拟器、沙箱或真实系统中复现交互与状态变化；
4. **判定测试**：联合终态、轨迹、规则、Judge 和人工证据判断正确性与副作用；
5. **施压测试**：通过重复运行、变形、对抗、故障注入和压力条件暴露不稳定与安全问题；
6. **诊断与回归**：定位责任步骤和传播路径，将失败重放并沉淀为持续回归资产。

这六项不是互斥论文类别，而是一条 Agent Testing 生命周期。论文可以跨阶段，但锚点案例按其最独特的贡献放置。

质量风险作为第二层覆盖：功能正确性、可靠性、安全性、过程合规、可诊断性、效率与成本。Agent 类型作为第三层案例标签：工具/Web、代码、记忆、多智能体及通用工作流 Agent。

## 相比原有八分类的改进

- 将“可控环境”和“可观测性”视为贯穿多个活动的基础条件，不再与具体测试技术强行并列。
- 将普通扰动、重复可靠性、安全对抗和故障注入统一放在“施压测试”下，再以风险和扰动来源二级区分。
- 将 Judge、规则 Oracle、过程评估和 evaluator 元评测放入同一个“判定测试”问题域，突出“谁来判断判断者”。
- 将失败归因、反事实回放和线上调试连接到回归，而不是把诊断当作测试结束后的孤立任务。
- 在生命周期最前面补上现有语料薄弱的“定义测试”，避免直接从自动生成或 benchmark 开始讲。

## 暂时识别出的覆盖盲区

以下主题在现有 25 篇核心表中缺少足够锚点证据，下一轮检索应优先验证：

1. 需求、政策、工具契约到可执行 Agent 测试规范的转换；
2. Agent 专属覆盖准则，以及覆盖与真实缺陷发现之间的关系；
3. 语义等价输入、环境变换和工具变更下的变形/差分测试；
4. 长期记忆污染、跨会话状态漂移和多用户隔离测试；
5. 并发、竞态、幂等、补偿事务和真实工具状态故障；
6. 生产 incident 驱动的故障模型与真实外部效度；
7. Agent harness、工具 schema、模型版本变化导致的持续回归；
8. 轨迹采集、隐私保护和可诊断性之间的可量化权衡；
9. 能耗、延迟、成本预算等非功能测试是否已形成独立方法路线。

## 当前结论

“测试活动/生命周期”比“Agent 类型”或“质量风险”更适合作为面向入门技术读者的 PPT 主轴。它既能解释大家在做什么，也能说明这些工作如何共同组成一套测试闭环。该结论仍需通过无预设分类的外部检索和综述参考文献追踪进行反证。
