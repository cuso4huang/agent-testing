## 2. 研究问题

论文研究如何在接近真实、可执行、带状态的工具环境中，同时测量 LLM 智能体的正常任务能力和受到间接提示注入后的安全性。其核心问题包括：

1. 如何避免只把一段恶意工具输出直接喂给模型、却不测试规划和多次工具调用的静态评测；
2. 如何用环境状态上的确定性检查函数，而不是另一个可能同样被注入影响的 LLM，判断用户目标和攻击者目标是否达成；
3. 如何让基准可持续加入新的任务、攻击和防御，并支持针对具体防御的自适应攻击；
4. 如何显式展示安全性与任务效用之间的权衡。

章节依据：第 1 节提出研究缺口；第 3 节定义环境、任务、攻击与判定机制；第 3.4 节定义指标；第 4 节进行攻击、防御和消融实验。

## 3. 被测试的智能体类型

- 以文本推理和函数调用 API 驱动的通用工具调用智能体；
- 可连续调用多个读写工具，并与有状态应用交互；
- 覆盖办公工作区、Slack、旅行预订和电子银行四类应用；
- 被测骨干包括 Gemini 1.5 Flash/Pro、Claude 3 Sonnet/Opus、Claude 3.5 Sonnet、GPT-3.5 Turbo、GPT-4 Turbo、GPT-4o、Llama 3 70B、Command R+。

论文不测试多模态智能体，也没有测试长期保持同一上下文、跨多个用户任务持续运行的智能体。

## 4. 测试或评估方法

AgentDojo 把一次测试建模为“环境初始状态 + 用户任务 + 可用工具 + 可选的攻击注入 + 执行轨迹 + 环境终态”。

- **环境与状态**：四个应用环境由可变 Python 对象表示；工具能够读取或修改状态（第 3.1 节）。
- **用户任务**：自然语言任务同时带有 ground-truth 工具调用序列和确定性 `utility` 检查函数。检查函数读取模型输出以及执行前后的环境状态（第 3.1 节、图 5）。
- **攻击任务**：恶意目标同样带有 ground-truth 调用序列和确定性 `security` 检查函数（第 3.1 节、附录图 10）。
- **注入位置**：第三方可控数据中设置占位符；根据完成用户任务必需的工具调用，选择现实中确实会被智能体读取的注入点（第 3.3 节、附录 A）。
- **动态基准**：攻击以函数形式实现，可以读取攻击目标并生成注入文本；框架鼓励在发布新防御时设计自适应攻击，而不是把默认攻击当作最终安全证明（第 3.3 节、附录 F.5/F.9）。
- **防御对比**：数据定界、提示注入分类器、重复用户提示、预先筛选工具四类方案（第 4.3 节）。

这一设计的关键是将安全 oracle 放在环境状态和显式副作用上，而非仅判断文本是否“看起来安全”。

## 5. 数据集、环境或基准

第 3.1 节和表 1给出的初始版本包含：

| 环境 | 工具 | 用户任务 | 攻击目标 | 安全测试数 |
|---|---:|---:|---:|---:|
| Workspace | 24 | 40 | 6 | 240 |
| Slack | 11 | 21 | 5 | 105 |
| Travel | 28 | 20 | 7 | 140 |
| Banking | 11 | 16 | 9 | 144 |
| 合计 | 74（论文另有“70”记载） | 97 | 27 | 629 |

任务最长需要约 7,000 个 GPT-4 token 的数据上下文、约 4,000 token 的工具说明，并可能串联最多 18 次工具调用；攻击目标需要 1–20 个步骤。环境数据均为虚构数据，由作者手工构造或使用 GPT-4o、Claude 3 Opus辅助生成，再由作者检查语法、正确性和相互一致性（第 3.1 节、附录 F.7）。

数据卡将总样本写作 124 个任务（97 个用户任务 + 27 个攻击任务），环境数据约 136 KB，初始数据版本为 v1.0（2024-06）。

## 6. 评价指标

第 3.4 节定义三个主指标：

1. **Benign Utility**：无攻击时正确完成用户任务的比例；
2. **Utility Under Attack**：存在攻击时，完成用户任务且没有对抗性副作用的安全案例比例；其补数有时称 untargeted ASR；
3. **Targeted Attack Success Rate (ASR)**：环境检查确认攻击者目标实际完成的比例。

对多种攻击的组合，论文还计算“任一攻击成功即成功”的逐样本最大值，模拟会为具体任务选择最有效攻击的自适应攻击者。所有主结果用环境状态的二元检查函数确定，附录说明比例置信区间使用 `statsmodels.stats.proportion.proportion_confint` 计算 95% 置信区间。

## 7. 实验设计

- 每个被测智能体运行 97 个良性任务和完整的 629 个安全测试案例（第 4 节）。
- 除 Llama 3 70B 外，使用模型提供方的正式函数调用接口；Llama 3 通过额外工具调用提示适配。Claude Sonnet 使用 Anthropic 推荐的附加 tool-use 提示。完整提示列于附录 B。
- 基线攻击为“Important message”：声称存在必须先完成的重要附加任务，并可带模型名与用户名。
- 攻击消融比较 `TODO`、`Ignore previous instructions`、InjecAgent 提示、Important message，以及逐任务选择最强提示的 `Max`。
- 攻击者知识消融分别使用正确或错误的用户名、模型名。
- 防御实验固定以 GPT-4o 为主，比较无防御、数据定界、DeBERTa 提示注入检测器、每次工具调用后重复用户提示、调用前工具筛选。
- 论文还分析注入在工具返回文本中的相对位置、不同攻击目标和不同环境的难度，以及面向中止执行的拒绝服务攻击。
- 复现实验运行成本估算：629 个 GPT-4o 安全案例约 35 美元，97 个良性案例约 4 美元（附录 D；这是论文当时 API 价格下的估算）。

## 8. 主要发现

以下数值均来自论文的对应表格或章节，不能外推到当前模型版本：

- 表 3 中，Claude 3.5 Sonnet 的良性效用最高，为 78.22%；GPT-4o 为 69.00%。GPT-4o 在攻击下效用为 50.08%，targeted ASR 为 47.69%。Claude 3 Opus 的三项分别为 66.61%、52.46%、11.29%。
- 模型能力与 targeted ASR 呈现“更会用工具也更可能完成恶意目标”的现象；但低 ASR 不能脱离低良性效用解释。例如 Command R+ 的 targeted ASR 只有 0.95%，良性效用也只有 25.44%（第 4.1 节、表 3）。
- 多数模型在攻击下损失约 10–25 个百分点的绝对效用。不同环境差异很大；GPT-4o 在 Slack 套件的攻击成功率可达 92%，而需要同时预订最贵酒店和外泄信息的 Travel 攻击任务在该实验中为 0%（第 4.1 节、图 7）。
- 注入越接近工具输出末尾越有效，最高可接近 70% 平均成功率（第 4.1 节、附录 D/图 21）。
- 攻击措辞影响显著。表 4 中 Important message 的 targeted ASR 为 57.7%，而 TODO、Ignore previous、InjecAgent 提示分别为 3.66%、5.41%、5.72%；逐任务组合攻击的 untargeted ASR 从 Important message 的 49.9% 升至 68.36%。
- 攻击者知道正确用户名和模型名只使表 2 的 ASR 从 45.8% 小幅升至 47.7%；错误猜测会降至约 23%，说明错误的个性化信息会削弱攻击。
- 表 5 中，GPT-4o 无防御时良性效用 69.00%、攻击下效用 50.01%、targeted ASR 57.69%。数据定界的三项为 72.66%、55.64%、41.65%；PI 检测器为 41.49%、21.14%、7.95%；重复提示为 85.53%、67.25%、27.82%；工具筛选为 73.13%、56.28%、6.84%。
- 工具筛选之所以有效，主要因为许多良性任务只需读工具，而攻击需要写工具；17% 的案例中，良性任务所需工具已经足以实施攻击，此时筛选不能提供隔离（第 4.3 节）。

论文正文和表格个别数字因实验切片或论文更新存在差别，例如正文将工具筛选 ASR 概述为 7.5%，表 5 为 6.84%；综述引用具体数字时应指明表格和设置。

## 9. 局限性

论文第 5 节和第 4.3 节明确指出：

- 初始攻击和防御较简单；默认攻击不能证明一个新防御安全，必须补做针对该防御的自适应攻击；
- 任务与确定性检查函数主要由人工编写，扩展到更多领域成本较高；
- 工具筛选适合事先可判断工具集合的任务，不适合下一步依赖工具返回结果的开放式规划；
- 未覆盖多个任务共享长期上下文的场景；攻击可等待未来权限更高的工具出现；
- 未覆盖多模态输入；
- 尚未对注入长度、格式和攻击者可控位置施加更现实的约束；
- 均为虚构环境和数据，不能等同于生产系统；
- closed-source API 模型和服务端实现会变化，论文结果是特定时间的快照；
- 工具数量在正文/数据卡内部有 74 与 70 的不一致，复用数据时应以实际仓库版本为准。

## 10. 可复现性信息

- 代码、任务、环境、工具和说明公开，MIT 许可证；可通过 `pip install agentdojo` 安装（附录 E）。
- 仓库包含运行日志/对话 JSON、重画图表的 Jupyter Notebook、依赖文件和创建新工具/任务/攻击的教程。
- 论文提供默认 agent prompt、Claude/Llama 适配提示、防御提示和四种攻击提示（附录 B）。
- 数据生成来源和人工校验流程写入数据卡；所有环境数据为虚构数据。
- 模型家族和 API 接入方式有说明，但论文正文未给出所有闭源 API 的不可变模型快照标识；随着服务更新，精确复现仍受限制。
- 报告了比例的 95% 置信区间和当时的近似 API 成本。
- 框架维护策略为语义化版本；因此复现实验应锁定 AgentDojo 版本、任务套件版本、模型端点日期和攻击实现 commit。

## 11. 与“智能体测试”研究的关系

AgentDojo 展示了智能体安全测试区别于普通 LLM 内容评测的最关键设计：

- oracle 检查真实工具副作用和环境终态，而非只给文本打分；
- 用户任务和攻击目标可以同时成功，必须分别测 utility 与 security；
- 一次案例包含多步规划、工具选择、工具参数、状态变更和不可信工具输出；
- 基准必须支持自适应攻击和持续版本化，静态攻击集合只能说明对已知样本的鲁棒性；
- 低攻击成功率必须与正常任务能力联合解释，否则“什么也不会做”的智能体会被误判为安全。

## 12. 可借鉴的工程实现

1. 为每个任务编写执行前/执行后状态断言，并把安全断言独立于任务成功断言；
2. 将攻击点放入邮件、网页、Slack 消息、文件等第三方数据源，而不是直接拼在用户输入后；
3. 将环境、工具、任务、攻击、防御做成插件接口，测试流水线按笛卡尔积生成案例；
4. 保存完整轨迹、工具参数、执行前后状态和模型版本，支持回归差异分析；
5. 把读写权限分开，并测试预先工具白名单、最小权限和分阶段授权；
6. 对每项防御建立 adaptive red-team 回归集，不能只复跑发布时的默认攻击；
7. 对随机模型至少重复运行并报告置信区间、pass-rate 分布、token/费用/延迟；
8. 对长期会话增加“攻击先写入、之后权限出现再触发”的延迟攻击场景，这是原论文未覆盖但由其局限直接导出的扩展。

## 14. 可以支持综述中的结论

- 智能体测试应以**轨迹、工具副作用和环境终态**为核心，而不仅是最终文本；
- 安全性与正常任务效用必须联合报告，不能用拒绝一切换取表面安全；
- 间接提示注入的风险来自“数据与指令无类型边界”，并会通过工具返回值进入规划循环；
- 最小权限和工具隔离能显著降低一部分攻击面，但不是完整解决方案；
- 攻击措辞、位置和对防御的适配会大幅改变测得的安全性，静态攻击基准容易高估防御；
- 确定性 oracle 比 LLM judge 更适合判断可程序化的权限和状态违规；
- 当前基准仍缺少长期会话、多模态、复杂权限演化和生产级外部系统，构成后续研究空白。
