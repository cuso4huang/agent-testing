# GAIA：结构化阅读笔记

## 1. 基本信息

- **标题**：GAIA: A Benchmark for General AI Assistants
- **作者**：Grégoire Mialon, Clémentine Fourrier, Craig Swift, Thomas Wolf, Yann LeCun, Thomas Scialom
- **年份**：2024（正式发表）；arXiv 首发于 2023
- **会议或期刊**：International Conference on Learning Representations（ICLR 2024）
- **DOI**：未核验到正式 DOI，不猜测
- **arXiv ID**：2311.12983
- **正式版本和预印本关系**：2023 年 arXiv 预印本后成为 ICLR 2024 论文；正式引用优先使用 ICLR 版本，arXiv 作为公开全文入口。
- **数据/榜单**：<https://huggingface.co/gaia-benchmark>

## 2. 研究问题

GAIA 研究如何用“人类概念上简单、机器执行链复杂、最终答案容易验证”的真实问题评测通用 AI assistant。它避免继续提高专业知识难度，而要求系统组合 Web 浏览、推理、代码、多模态和多文件读取等工具能力，并用唯一短答案作为 proof-of-work 式的端到端结果。

## 3. 被测试的智能体类型

- 通用问答/研究助手，可自行或在人类选择下调用浏览、代码执行、文件读取和第三方插件。
- 包括纯 GPT-4/GPT-4 Turbo、人工选择插件的 GPT-4、以 GPT-4 为后端且自动选工具的 AutoGPT。
- 输入为文本问题，部分附带图像、音频、PDF、电子表格、演示文稿、压缩包等文件。
- GAIA 测的是系统级最终答案，不规定统一 action API；因此比 stateful 环境中的 tool-call benchmark 更开放，但不能细粒度验证具体工具调用。

## 4. 测试或评估方法

每道题零样本给助手，并使用统一前缀要求输出 `FINAL ANSWER`。第 3.2 节定义 **quasi exact match**：答案必须是短字符串、数字或逗号分隔列表，根据 ground-truth 类型做有限规范化后与唯一正确答案匹配。

题目分三级：

- Level 1：通常不需工具，或最多一个工具且不超过约 5 步；
- Level 2：大致 5–10 步并组合不同工具；
- Level 3：需要更长的动作链、任意数量工具和更开放的世界访问。

分级是依据题目创建者实际使用的步骤/工具的代理标签，不是硬约束，也不是对所有可行解路径的最小复杂度证明。

## 5. 数据集、环境或基准

- **466 道人工设计题**；其中 166 道带标注的 developer set，300 道答案保留用于 leaderboard。
- 表 4 按难度为 Level 1 146、Level 2 245、Level 3 75。
- 人类标注的能力需求：355 题涉及 Web browsing、154 题 coding、138 题 multi-modality、129 题 diverse filetype reading，32 题不需这些工具（图 3；类别可重叠）。
- 附件类型包括 xlsx 29、png 18、pdf 15、txt 13、jpg/mp3 各 7、csv 6，并有 docx、pptx、zip、xml、json、Python、音频/视频等（附录 C，图 6）。
- 题目由作者和受偿标注者创建，常基于可靠网页、给定文件或自包含谜题；要求答案不会直接以完整文本出现在 Web 上。
- 每题再由两位独立标注者求解；若三方答案不一致则修复或删除。623 个候选题经 1,246 次验证标注后，68% 最终有效（附录 D，表 3）。

## 6. 评价指标

- **Accuracy / Score**：quasi exact match 后的正确率，分别报告 Level 1–3。
- **Average time to answer**：按等级比较 API、人工、搜索和 AutoGPT。
- **Human score**：验证标注者在有效题目上的正确率，而非专家上限。
- **按能力得分**：Level 1 中按浏览、代码、多模态、文件读取等标签拆分。
- 论文不评分轨迹、调用正确率、部分进度、恢复质量、安全、token/货币成本或工具副作用。

## 7. 实验设计

- 比较 GPT-4、GPT-4 Turbo、AutoGPT（GPT-4 backend）、GPT-4+plugins、人工搜索引擎基线和人类。
- 有直接 API 时每个模型运行三次并报告均值；时间从 20 道题的 API 运行估算。
- GPT-4+plugins 没有 API：作者按对任务能力的判断人工选择 Advanced Data Analysis 或最多三个插件，常用链接阅读、Web 浏览和计算工具。因此这是带人工 oracle tool selection 的能力上界估计，而非可直接复现的自主 agent。
- AutoGPT 使用论文给出的 git commit `ed172dec1947466cc0942abf75bb77b027cd433d`。
- 系统提示和答案格式完整给出（图 2、附录 D.1）；论文没有为所有闭源模型提供稳定的精确 API snapshot 和完整工具调用日志。

## 8. 主要发现

1. **人类简单并不意味着 agent 简单。** 摘要报告人类总体约 92%，GPT-4+plugins 约 15%；说明主要瓶颈是可靠完成多步链，而非单项专业知识难度。
2. **难度分级与系统表现一致。** 表 4 中 GPT-4 为 Level 1/2/3 = 9.1±2.5 / 2.6±0.6 / 0；GPT-4 Turbo 为 13.0±2.1 / 5.5±1.4 / 0；GPT-4+plugins 为 30.3 / 9.7 / 0。到 Level 3，所有测试系统均为 0。
3. **工具可显著提升能力，但自动编排仍弱。** 人工选插件的 GPT-4 显著优于无工具 GPT-4；AutoGPT 为 14.4 / 0.4 / 0，在 Level 2 反而低于纯 GPT-4，作者认为可能与 API prompt、生成参数及工具编排有关。
4. **人工插件结果是 oracle，不是公平自主基线。** 插件根据每题人工选择，且插件会变化/下架；论文明确称该分数难以精确复现。
5. **简单搜索不足以解决组合题。** 搜索引擎基线为 7.4 / 0 / 0，说明答案通常不能从搜索结果首页直接抄取，而需组合、转换或处理附件。
6. **人类表现随难度下降但仍高。** 表 4 为 93.9 / 91.8 / 87.3，平均时间 6.8 / 10.5 / 17.7 分钟；验证阶段汇总人类正确率 92%。
7. **工具链错误无法由最终分数定位。** 第 5–6 节明确讨论：某个视觉、浏览或代码模块失败都会反映为整题错误，但 GAIA 不归因到子模块；OpenAI API 当时也不提供完整调用日志。
8. **Web 依赖会随时间衰减。** 论文承认信息消失、页面变化和训练数据污染，需要逐年修复/淘汰失效问题并新增题目。

## 9. 局限性

第 6 节明确列出：

- 不评估得到答案的轨迹；正确答案可能来自错误/危险过程，错误答案也无法定位到规划、工具选择或某一步。
- 只评估当时最强、能调用工具的少数闭源系统；缺少可记录完整 tool trace 的开源模型对比。
- 构造唯一、无歧义的现实问题成本高：每题含两名额外验证者和修复平均约需两小时，仍可能残留歧义。
- 为保证唯一答案，部分题目包含大量限定，和真实用户的欠规格询问不完全一致。
- 所有问题是主流英语，很多证据来自英语网页，缺乏语言和文化多样性。

其他重要边界：

- quasi exact match 对最终格式敏感，不测解释质量、证据引用或近似正确的部分工作。
- GPT-4+plugins 由人类选择工具，混入人工规划；不同 agent 的可用工具集合并不严格等价。
- 动态 Web 会造成 oracle 衰减、robots.txt 变化和答案版本冲突。
- 不测试写操作、真实交易、权限、提示注入、数据泄露和工具调用安全。

## 10. 可复现性信息

- **数据/评分器**：Hugging Face 发布 developer questions、附件、元数据和评分函数；300 个 test 答案隐藏用于榜单。
- **提示**：图 2 与附录 D.1 给出统一 system/prefix prompt 和答案格式。
- **标注协议**：问题创建要求、两人独立验证、修复/删除规则和验证统计完整披露。
- **模型运行**：API 可用时三次运行；AutoGPT commit 固定。GPT-4+plugins 需人工操作且插件不可锁定，论文明确标注不可精确复现。
- **模型/参数缺失**：闭源 GPT-4 产品/API 快照、所有生成参数、插件版本和完整 tool trace 未充分固定。
- **动态依赖**：证据来自开放 Web；作者建议标日期、选稳定来源、检查 robots.txt，并维护动态版本。

## 11. 与“智能体测试”研究的关系

GAIA 是端到端黑盒验收测试的代表：只要系统能在开放工具空间中得到唯一结果，就不限制实现路径。它尤其适合检验工具编排、跨模态/文件处理与多步推理的组合可靠性，并揭示“每个组件看似可用、整链仍失败”的级联效应。它同时是轨迹测试的反例边界：最终答案清晰，却无法检查错误调用、安全性、成本或最早失败步骤。

## 12. 可借鉴的工程实现

- 用“复杂执行、短且唯一答案”的任务降低最终 oracle 成本。
- 将公开开发集与隐藏测试答案分离，减少直接过拟合和答案泄漏。
- 每题保存来源、证据版本、所需能力、人工解题步骤、工具、耗时和附件哈希。
- 让两名独立人员重新求解；将分歧作为题目缺陷而非简单多数投票。
- 在 GAIA 式最终得分之外强制记录结构化 tool trace，增加逐步合法性、引用来源、费用和安全策略检查。
- 对动态网页建立定期健康检查、失效题隔离和版本化替换机制。
- 为工具集合和人工干预定义清晰等级，避免把人工选工具的 oracle 分数与完全自主 agent 混排。

## 14. 可以支持综述中哪些结论

- 智能体基准可用唯一短答案评估开放工具链的端到端任务完成能力。
- 工具访问能提高表现，但工具自动选择与长链编排仍可能比人工选工具差很多。
- 组件错误会级联为最终失败；只看答案无法归因到规划、浏览、代码、文件或视觉模块。
- 动态 Web 基准必须处理证据版本、页面衰减、robots 约束和数据污染。
- 人工双重验证能提高 oracle 可信度，但无歧义现实题构造成本很高。
- GAIA 对轨迹、安全、权限、成本和多语言覆盖不足，适合与 trajectory-level evaluator 结合而非单独作为完整质量体系。
