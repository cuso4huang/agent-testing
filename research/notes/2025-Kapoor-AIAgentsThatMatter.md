## 2. 研究问题

论文不是提出一个新的任务智能体，而是审视智能体基准和评测实践本身，主要回答五个问题：

1. 只按准确率排序，是否会把单纯增加推理次数和成本误认为智能体架构进步？
2. 能否把准确率与经济成本作为联合优化目标，而不只在模型确定后被动统计成本？
3. 模型研发者和下游应用开发者需要的基准是否不同？
4. 智能体是否会利用公开基准任务、环境和脚本中的捷径，导致排行榜成绩不能外推到真实场景？
5. 当前智能体评测是否因脚本、任务子集、环境状态和统计报告不统一而缺乏可复现性？

论文的核心论点是：智能体比普通单次模型调用更昂贵、更随机、更依赖外部环境，也更容易针对小规模公开测试集进行程序化过拟合，因此需要重新设计评测规范，而不能直接沿用普通 LLM 的静态输入—输出基准。

## 3. 被测试的智能体类型

论文的实证案例覆盖：

- HumanEval 上的代码生成/调试智能体：LATS、LDB、Reflexion；
- 作者构造的简单代码智能体基线：Retry、Warming、Escalation；
- HotPotQA 上基于 DSPy、检索和多步调用的问答智能体；
- WebArena 上的网页智能体 STeP，用于分析硬编码策略和环境捷径；
- NovelQA 上的长上下文模型与 RAG 智能体，用于区分模型评测和下游工程评测。

它并未系统测试多智能体协作、具身智能体或安全攻击，但提出的方法原则可扩展到这些类型。

## 4. 测试或评估方法

论文采用“方法学分析 + 多个复现实验/案例研究”的设计。

### 4.1 成本控制的二维评测

作者在 HumanEval 上重新运行公开智能体，并加入三个简单基线：

- `Retry`：温度为 0，样例测试失败时最多重试五次；
- `Warming`：重试过程中把温度从 0 逐渐升至 0.5；
- `Escalation`：从 Llama-3-8B 开始，失败后依次升级到 GPT-3.5、Llama-3-70B 和 GPT-4。

以准确率和总 API 成本形成凸 Pareto 前沿；若另一个系统在准确率和成本上均显著更优，则前者被支配。论文同时绘制准确率—推理时间曲线（Section 2；Appendix A）。

### 4.2 准确率—成本联合优化

作者修改 DSPy 的优化流程，并用 Optuna 对温度、few-shot 数量、样例选择和格式指令进行多目标搜索，目标为最大化 HotPotQA 检索准确率并最小化提示 token/推理成本。论文区分一次性的固定优化成本和每次部署调用产生的可变成本（Section 3；Appendix B）。

### 4.3 外推与捷径审计

作者提出四种预期泛化层级：distribution-specific、task-specific、domain-general 和 fully general。测试集需要分别留出同分布样本、分布外样本、任务或整个领域。作者据此审查 17 个智能体基准，并以 WebArena/STeP 展示公开任务如何诱发硬编码策略（Section 5；Table 1；Appendix Table A4）。

### 4.4 可复现性审计

作者复现 HumanEval 和 WebArena 上五篇智能体工作的评测，检查任务子集、样例测试、真实测试调用、模型身份、环境限流和成功标签，汇总不一致来源（Section 6；Appendix Tables A6-A7）。

## 5. 数据集、环境或基准

- **HumanEval**：164 个代码任务。作者采用 LDB 修改版，因为它为原版缺少样例测试的 3 个任务补齐了测试。该选择本身也是论文讨论“基准版本不统一”的实例。
- **HotPotQA**：用 ColBERTv2 检索 Wikipedia。100 个训练样本用于优化，其中联合优化再分为 50 个候选收集样本和 50 个开发/验证样本；测试集使用 200 个样本（Section 3.1）。
- **NovelQA**：长篇小说问答；比较全文长上下文输入和每题检索 10 个、每个 1,000 字符片段的 RAG 设置（Section 4.1；Appendix D）。
- **WebArena**：812 个网页任务、六类自托管网站和两个工具；论文重点审计 STeP 的任务专用策略、Reddit 限流和自动登录问题（Section 5.1；Appendix E）。
- **17 个智能体基准的调查样本**：来自 AgentBench、AgentBoard、OpenDevin、ICLR 2024 LLM Agents workshop 及作者已知基准（Appendix C）。

## 6. 评价指标

- HumanEval accuracy；
- 总 API 美元成本、输入/输出 token 成本和总推理时间；
- 五次运行的均值、最小值、最大值和基于 Student's t 分布的 95% 置信区间；
- 准确率—成本、准确率—时间 Pareto 前沿；
- HotPotQA ground-truth 文档是否全部检索到的 retrieval accuracy；
- 每 100 次 HotPotQA 推理的可变成本与一次性优化固定成本；
- NovelQA 问答准确率、总成本和单问题成本；
- 基准是否有 holdout、holdout 是否匹配其宣称的泛化层级；
- 报告准确率与作者复现准确率之间的差异；
- 环境/脚本层面的复现缺陷类别。

论文明确主张下游评测应同时发布美元成本和输入/输出 token 数。美元价格会变化，token 数允许后续使用者按新的服务商和价格重算。

## 7. 实验设计

### HumanEval

- 对 LATS、LDB、Reflexion、零样本模型和三个简单基线，在 164 个任务上各运行五次；
- 主实验使用 `gpt-3.5-turbo-0125` 和 `gpt-4-turbo-2024-04-09`；
- 另用 2023 年 6 月 GPT-3.5/GPT-4 版本做鲁棒性复查；
- 记录每次模型调用成本与推理时间；
- 个别第三方 agent 原实现的任务子集、测试脚本和模型配置被重新校正，差异在 Appendix E 中逐项说明。

### HotPotQA

- 五种设计：uncompiled、仅格式指令、DSPy few-shot、DSPy random search、joint optimization；
- 分别以 GPT-3.5 和 Llama-3-70B 为底座；
- Optuna 进行 16 次 trial，模块温度从 `{0.0, 0.2, 0.4, 0.6}` 中选择，每个提示最多 8 个 few-shot 样例；
- 测试集重复运行五次并计算成本与准确率（Section 3.1；Appendix B）。

### 其他研究

- NovelQA 因成本过高只运行一次，作者明确说明这一点；
- 对 17 个基准进行 holdout/泛化层级编码；
- 复查 WebArena、HumanEval 的公开代码、轨迹和评估结果。

## 8. 主要发现

### 8.1 成本控制改变了“最佳智能体”的结论

- HumanEval 中，Warming (GPT-4) 的平均准确率为 93.2%，总成本 2.45 美元；LATS (GPT-4) 为 88.0%，总成本 134.50 美元。两者均为 164 题、五次运行的均值（Appendix Table A1）。
- Warming 与最佳复杂架构之间没有显著准确率差异，而 LATS 成本超过 Warming 50 倍。论文据此认为，原实验不足以证明规划、反思或调试本身是 HumanEval 增益来源；简单重试同样可能造成提升（Section 2.3）。
- 对相近准确率，不同系统成本可相差近两个数量级，因此只按 accuracy 排行会把推理预算差异误判为架构进步。

### 8.2 联合优化能降低可变成本

- 在 GPT-3.5 上，联合优化 retrieval accuracy 为 0.509、每 100 次推理可变成本 0.174 美元；DSPy random search 为 0.495/0.376 美元，few-shot 为 0.470/0.384 美元（Appendix Table A3）。
- 在 Llama-3-70B 上，联合优化为 0.601/0.374 美元，DSPy random search 和 few-shot 分别为 0.617/0.643、0.622/0.661 美元。
- 正文概括为：在准确率相近时，GPT-3.5 可变成本降低约 53%，Llama-3-70B 降低约 41%（Section 3.2）。
- 联合优化要先支付固定成本；Appendix Figure A6 给出的交叉点约为 Llama-3-70B 1,332 次、GPT-3.5 1,275 次推理。因而只有在足够高调用量下才整体更便宜。

### 8.3 基准污染不仅是训练数据泄漏

- 调查的 17 个智能体基准中，7 个没有 holdout 且未说明未来会添加；已有 holdout 的 10 个中，只有 5 个与论文判定的泛化层级匹配（Appendix Table A4）。
- WebArena 的 STeP 把特定任务策略硬编码为可组合 policy，例如根据固定 URL 结构直接构造用户主页地址。这对已知任务有效，但网站结构改变或面对新网站时会失效（Section 5.1）。
- 由于智能体代码可以直接访问公开测试任务，智能体基准的“污染”可能表现为显式条件、检索表或环境特定脚本，比普通预训练数据污染更直接。

### 8.4 统计不确定性和复现差异不可忽略

- 论文以五次运行展示同一 agent 的准确率和成本波动，并指出很多原论文没有误差条；高成本是重复运行不足的重要原因（Section 6）。
- Appendix Table A7 中，原论文报告的 GPT-4 HumanEval baseline 为 75.0%，复现实验五次均值为 89.6%；Reflexion 报告 91.0%，复现均值为 87.8%。作者把差异主要归因于基准版本、任务子集、测试实现和模型配置不统一，而非简单指责原作者。
- WebArena 还受 Reddit 限流、自动登录未实现和任务顺序影响，说明动态环境破坏了普通基准默认的“任务互相独立、顺序无关”假设（Section 6；Appendix Table A6）。

## 9. 局限性

- 论文的结论来自 HumanEval、HotPotQA、NovelQA 和 WebArena 等案例，不能证明所有领域中的复杂规划/反思架构都无效；作者也明确指出更难的 SWE-bench 任务可能得到不同结论。
- HumanEval 采用 LDB 修改版而非唯一标准版本。虽然这是论文要揭示的问题，但也意味着主结果绑定于该版本。
- HumanEval 与 HotPotQA 只重复五次；Appendix Figure A5 明确说明 HotPotQA 的置信区间只涵盖测试集内方差，未计入优化过程和重新采样造成的不确定性。
- NovelQA 因费用只运行一次，因此不能用其小幅准确率差异证明统计显著性。
- API 美元成本绑定于 2024 年 4—6 月的模型价格、服务商和计费方式；论文通过同时报告 token 数部分缓解，但无法消除价格漂移。
- 对 17 个基准的“预期泛化层级”在原作者未明确说明时由本文作者推断，Appendix C 明确称其为 best guess。
- Web 环境限流、第三方仓库变化及闭源模型后端更新仍会影响复现。
- 本地全文为 arXiv v1；正式 TMLR 版本的身份已核验，但本次阅读没有逐行核对正式版是否修改个别实验或措辞。

## 11. 与“智能体测试”研究的关系

该文直接给出智能体测试与普通 LLM 评测的关键差异：

- 智能体可以通过增加调用、重试和搜索无限提高成功机会，因此测试必须控制预算；
- 外部环境、工具状态和任务顺序进入测试系统，测试执行器自身也可能成为故障源；
- 智能体能把公开测试任务直接编码进策略，必须按宣称的泛化范围设计秘密 holdout；
- 随机性和高成本共同要求在置信区间、样本规模和预算之间做明确权衡；
- 面向科研的模型比较与面向采购的下游系统比较不能使用同一成本代理。

## 12. 可借鉴的工程实现

1. CI 中把任务成功率、token、美元成本、墙钟时间和工具调用数作为联合门槛，而不是只设成功率阈值。
2. 对所有 agent 建立统一预算包络：最大模型调用、最大 token、最大工具调用、最大时间和最大费用。
3. 输出成本—准确率—延迟 Pareto 前沿，并提供按最新模型价格重新计算的配置。
4. 固定测试集之外设置秘密任务、秘密环境变化和时间后移数据，分别测试任务泛化、环境漂移和污染。
5. 同一版本至少重复运行多次，报告均值、区间和失败分布；高成本时先做功效分析或分层抽样。
6. 将 evaluator、环境 reset、任务顺序和服务限流纳入版本化测试规范。
7. 区分一次性优化成本和每次运行成本，并报告达到成本收益平衡所需的调用量。
8. 保存完整 trace、模型快照、提示哈希、工具版本、benchmark commit 和评估脚本 commit。

## 14. 可以支持综述中的结论

- 智能体测试必须做成本控制，否则重试预算会被误认为架构能力；
- 任务成功、成本和延迟应联合呈现为 Pareto 问题；
- 固定优化成本和部署可变成本必须分开核算；
- 智能体基准污染包括显式硬编码、环境捷径和公开任务过拟合；
- holdout 的粒度必须匹配系统宣称的泛化层级；
- 动态环境、任务顺序、限流和 evaluator 缺陷会破坏结果可复现性；
- 高成本评测导致重复运行不足，置信区间与统计功效是当前明显缺口；
- 科研模型评测与下游采购评测应采用不同的成本口径和基准设计。
